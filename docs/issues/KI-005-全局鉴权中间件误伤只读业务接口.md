## 当前判断

原登记将所有 `/api/*` 请求受 `X-Internal-Secret` 保护认定为“误伤”，证据不足。项目 README 将 FastAPI 定义为 Private API Gateway，而公开的 Cloudflare Worker 会在代理请求中注入内部密钥。因此，无密钥直连请求返回 403 与当前安全边界一致，不能单凭 403 日志判定为缺陷。

## 代码证据

- [`api.py`](../../data-bridge/src/api.py) 对 `/api/*` 统一验证内部密钥。
- [`index.ts`](../../edge-app/src/index.ts) 从 Worker Secret 读取密钥并注入后端请求。
- `/health` 不在 `/api/*` 下，仍可供 Tunnel 与服务监控探测。

## 本地澄清

- 保留全局私有 API 鉴权，没有为了关闭文档问题而放宽安全边界。
- 中间件注释已明确：公开入口是 Worker，后端 API 是私有入口。
- Worker 现在显式传递原始客户端地址，后端仅在内部密钥有效时信任该地址。
- 测试通过 fixture 注入专用密钥，已移除基于 `"pytest" in sys.modules` 的运行时绕过。

## 当前开源版本决策

当前开源版本不提供第三方直连 FastAPI 的公开 API；浏览器入口统一经过
Cloudflare Worker，后端 `/api/*` 继续保持私有鉴权。如果未来要支持第三方
直接读取 FastAPI，应另建实现型 KI，先定义独立的公开 API 契约、身份认证、
授权范围和限流策略，而不是直接豁免现有只读路径。
