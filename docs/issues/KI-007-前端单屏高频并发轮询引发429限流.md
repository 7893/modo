# KI-007 · 前端单屏高频并发轮询引发429限流

- 状态：DONE
- 优先级：P1
- 更新日期：2026-09-23
- 适用范围：`edge-app/src/index.html`, `data-bridge/src/api.py`
- 关联：[已知问题看板](../KNOWN-ISSUES.md)

---

## 结论

在原实现中，前端每 15 秒触发一次 `fetchData()`：前两个请求串行等待，随后四个异步函数并行发起请求，共计 6 个 HTTP 请求。多标签页、手动刷新或刷新周期重叠会快速消耗后端限流额度；切换帷幕本身只触发图表 resize，不会发起刷新。

---

## 只读证据（2026-09-23）

### 1. 前端轮询单次无聚合触发 6 个请求
在 [`edge-app/src/index.html#L1108-L1395`](../../edge-app/src/index.html#L1108-L1395) 中：
```javascript
// 每 15 秒触发一次刷新循环：
const latestRes = await fetch(`/api/nodes/latest?_t=${timestamp}`);
const diagRes   = await fetch(`/api/ai/diagnostics?_t=${Date.now()}`);
const resAnom   = await fetch(`/api/analytics/anomalies?_t=${Date.now()}`);
const resHw     = await fetch(`/api/analytics/heatwave-status?_t=${Date.now()}`);
const resHourly = await fetch(`/api/analytics/hourly?hours=24&_t=${Date.now()}`);
const resFc     = await fetch(`/api/analytics/latency-forecast?_t=${Date.now()}`);
```
单标签页每分钟消耗：`(60s / 15s) * 6 = 24 requests/min`。

### 2. 后端默认限流阈值较低
在 [`data-bridge/src/api.py#L36-L37`](../../data-bridge/src/api.py#L36-L37) 中：
```python
RATE_LIMIT_REQUESTS = int(os.getenv("RATE_LIMIT_REQUESTS", "60"))  # requests per window
RATE_LIMIT_WINDOW = int(os.getenv("RATE_LIMIT_WINDOW", "60"))      # window in seconds
```
如果用户开启 3 个标签页，每分钟请求量达到 `72 req/min > 60`；即使单标签页，如果在快速切换导航栏时触发立即刷新，也会瞬间达到限流上限。

---

## 影响分析

1. **用户体验降级**：用户在正常操作监控大屏时，面板可能突然变红或报错显示“Too many requests”，数据图表停止更新。
2. **边缘代理压力**：Cloudflare Workers 收到 429 后无法有效命中缓存，浪费 Worker 执行调用额度。

---

## 治理目标与方案

1. **接口聚合（Backend for Frontend / BFF 模式）**：
   - 在后端或 Edge Worker 层面提供综合大屏快照接口 `/api/dashboard/overview`，单次调用即可返回节点状态、诊断告警、异常概览与预测数据，将 6 次请求收敛为 1 次请求。
2. **按需懒加载与节流**：
   - 切换到特定帷幕（Curtain）时，仅加载当前可见屏幕所必需的子接口；不在视野内的历史分析数据（如 24 小时分析图）按需延后请求。
3. **适当调优配置**：
   - 将生产环境默认限流阈值调整为与前端轮询频率更匹配的安全水位（如 120 req/min）。

---

## 本地修复进展（本地验证通过）

FastAPI 已新增 `/api/dashboard/overview` 聚合接口，Worker 提供对应代理，前端每轮只发起一次请求，并用 `fetchInFlight` 阻止刷新周期重叠。单元测试已模拟三个标签页各刷新五次的等价请求量，15 次聚合请求全部返回 200。真实部署的长时间观察属于运行验收，不阻塞开源代码关闭。
