# KI-006 · 内存限流器缺少键清理导致内存泄漏隐患

- 适用范围：`data-bridge/src/api.py`
- 关联：[已知问题看板](../KNOWN-ISSUES.md)

## 结论

在 [`data-bridge/src/api.py`](../../data-bridge/src/api.py) 中，滑动窗口速率限制器使用内存字典 `_rate_limit_store = defaultdict(list)` 存储各客户端 IP 的请求时间戳。虽然代码清理了列表内过期的时间戳，但**从未清理空列表所对应的 IP 键（Key）**。如果服务暴露在互联网遭受爬虫扫描或面对大量客户端 IP，字典中的键将无限制线性膨胀，导致内存泄漏风险。

---

## 只读证据（2026-09-23）

### 1. `check_rate_limit` 函数实现只增不减
在 [`data-bridge/src/api.py#L70-L91`](../../data-bridge/src/api.py#L70-L91) 中：
```python
# Rate limiter storage: {ip: [(timestamp, count)]}
_rate_limit_store: dict = defaultdict(list)


def check_rate_limit(client_ip: str) -> bool:
    """Check if client is within rate limit. Returns True if allowed."""
    now = time.time()
    window_start = now - RATE_LIMIT_WINDOW

    # Clean old entries
    _rate_limit_store[client_ip] = [
        t for t in _rate_limit_store[client_ip] if t > window_start
    ]

    # Check limit
    if len(_rate_limit_store[client_ip]) >= RATE_LIMIT_REQUESTS:
        return False

    # Record request
    _rate_limit_store[client_ip].append(now)
    return True
```
无论过期多少秒，`_rate_limit_store` 中曾经访问过的所有 IP 都会永久作为 key 驻留在进程内存中。即使时间戳列表变为空列表 `[]`，该键也不会被删除。

---

## 影响分析

1. **内存泄漏**：在公网环境下，端口扫描程序和爬虫通常会使用伪造或随机 IP。在长期无重启运行的生产进程中，全局字典的内存占用将持续单调递增。
2. **多进程不可信**：在多 Worker 部署场景下，内存字典在进程间无法共享，限流配额在多进程下实际被放大。

---

## 治理目标与方案

1. **全局过期清扫与容量上限**：
   - 仅弹出当前请求 IP 后立即重新写入并不能释放长期不活跃的其他 Key。
   - 应周期扫描全部桶，删除窗口外的客户端，并设置最大客户端数与最旧桶淘汰策略。
2. **生产推荐（可选）**：对于生产级高并发场景，推荐使用 Redis 或 Cloudflare Workers 原生 Rate Limiting 替代进程内简单字典。

---

## 本地修复进展（本地验证通过）

限流器已增加全局周期清扫、过期桶删除、最大客户端数和最旧桶淘汰；Worker 显式传递原始客户端 IP，后端只在内部密钥匹配时信任该头。
