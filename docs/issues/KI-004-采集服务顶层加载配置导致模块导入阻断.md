# KI-004 · 采集服务顶层加载配置导致模块导入阻断

- 状态：DONE
- 优先级：P1
- 更新日期：2026-09-23
- 适用范围：`data-bridge/src/ingest.py`, `data-bridge/tests/`
- 关联：[已知问题看板](../KNOWN-ISSUES.md)

---

## 结论

在 [`data-bridge/src/ingest.py`](../../data-bridge/src/ingest.py) 中，`TARGET_NODES = load_target_nodes()` 被直接定义在模块顶级作用域中。当 `config/nodes.json` 文件不存在时，该函数会直接抛出 `FileNotFoundError` 并中断 Python 运行。这导致任何第三方工具、外部导入或单元测试（如 `test_parser.py`）仅仅想复用纯文本解析函数时，都会因环境缺少配置文件而发生 Module Import Crash。

---

## 只读证据（2026-09-23）

### 1. 模块顶层强制读取未捕获异常
在 [`data-bridge/src/ingest.py#L103-L119`](../../data-bridge/src/ingest.py#L103-L119) 中：
```python
def load_target_nodes() -> list:
    """Load target nodes from nodes.json config file."""
    try:
        with open(_nodes_config_path, "r") as f:
            nodes = json.load(f)
            logger.info(f"Loaded {len(nodes)} nodes from config")
            return nodes
    except FileNotFoundError:
        logger.error(f"nodes.json not found at {_nodes_config_path}")
        raise
    except json.JSONDecodeError as e:
        logger.error(f"Invalid JSON in nodes.json: {e}")
        raise


# Target nodes (loaded from config)
TARGET_NODES = load_target_nodes()
```

### 2. CI 流程中为此专门增加了补丁规避
在 [`.github/workflows/ci.yml#L34-L37`](../../.github/workflows/ci.yml#L34-L37) 中，CI 步骤为了避免执行测试时因 `from ingest import parse_prometheus_metrics` 失败，专门增加了临时拷贝指令：
```yaml
      - name: Setup config files
        run: |
          cp config/nodes.json.example config/nodes.json
```
这表明只要新环境没有手工准备 `nodes.json`，即使仅仅运行无副作用的纯单元测试也会直接崩溃。

---

## 影响分析

1. **导入脆弱性（Import Fragility）**：破坏了 Python 模块化的基础规范，副作用污染了顶级作用域。
2. **测试与开发体验割裂**：开发者拉下代码后，在未配置真实节点的情况下执行任何涉及该模块的脚本均直接报错退出。

---

## 治理目标与方案

1. **配置读取优雅降级**：
   - 将 `load_target_nodes()` 改为安全读取：当 `nodes.json` 不存在时输出警告并返回空列表 `[]`，或在需要使用节点时进行懒加载（Lazy Load）。
2. **纯函数与副作用解耦**：
   - 将 `parse_prometheus_metrics` 等纯解析逻辑提取到独立的工具模块（如 `data-bridge/src/metrics_parser.py`），使测试无需导入具备网络/IO 副作用的采集主服务。

---

## 本地修复进展（本地验证通过）

Prometheus 解析器已移动到无 I/O 副作用的 `metrics_parser.py`。`ingest.py` 仅在 `main()` 启动服务时加载节点配置，并在空节点列表时安全跳过线程池创建。新增测试确认空节点不会创建线程池，完整 Python 测试集已通过。
